Put MikeDown in your app

MikeDown is the WYSIWYG markdown editor from the MikeDown desktop app and VS Code extension, packaged for the web. People edit formatted text with tables, task lists, code blocks and diagrams, and your app gets plain markdown back.

Install the web component npm install @mikedown/web-component @mikedown/core

Packages

Every package wraps the same editor and the same markdown. They share one version number, so install matching versions.

@mikedown/web-component

Any page, any framework

A <mikedown-editor> element that submits with forms like a textarea. For plain HTML, server templates, htmx, Svelte, Lit, or a CDN script tag.

npm install @mikedown/web-component @mikedown/core

@mikedown/core

The engine

The editor itself (TipTap for rich text, CodeMirror for the source view), which every package above wraps. Install it next to a wrapper, or use its bindMikeDownValue to write a binding of your own.

Which package do I need?

Pick by the framework that renders the page. Anything without its own package uses the web component.

  • ReactVite, Next.js, Remix, React Router @mikedown/react
  • VueVite, Nuxt @mikedown/vue
  • Angular 17 or laterStandalone components or NgModules @mikedown/angular
  • Svelte, Lit, Solid, Preact, BlazorOr any framework that renders custom elements @mikedown/web-component
  • Server-rendered forms and htmxRails, Django, Razor, Laravel, plain HTML @mikedown/web-component around your existing <textarea>
  • No build stepA static page, a CMS template, a prototype The web component from a CDN, one script tag

Bring your own AI

Give the editor a host.ai and it gains an AI tab in Settings and a Rewrite action for the selected text. Leave it out and nothing AI appears. MikeDown ships no provider SDK and makes no AI network calls of its own: your host.ai does the transport, to your backend or to a local model.

Tier 1: one method

Implement complete and proxy it to your backend. Your server picks the model, holds the keys and decides what may leave your network. Settings shows the on/off switch and the feature toggles, but no engine list.

Pass ai as host.ai in React and Vue, the [ai] input in Angular, or the ai property on <mikedown-editor> (a property only, never an attribute).

Tier 2: an engine registry

Add listEngines (and optionally testEngine, discoverModels, setSecret, requestCloudConsent) and Settings shows engines, models, capabilities and per-task routing. Core picks the engine and model for each request and hands it to your complete as req.route.

This example calls Ollama straight from the browser, which suits development: start Ollama with OLLAMA_ORIGINS set to your dev origin. In production, send these calls through your server. The helpers come from @mikedown/core/ai, which is pure functions with no network access.

Consent

Cloud engines stay off until the user turns on Allow cloud engines. Then, the first time a cloud engine would serve a request, core calls your requestCloudConsent(engineId); show a dialog naming the engine, its URL and what is sent, and resolve true or false. A host without it is treated as having consented. In tier 1 your backend owns this decision.

Try it here

Every demo on these pages uses a stub host that streams canned text from no server and no model. Open Settings (the gear) and the AI tab to see its engine, or select text and choose Rewrite.
